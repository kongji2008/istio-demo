# RequestAuthentication uses an inline `jwks`, not `jwksUri`

`jwksUri` is fetched by **istiod**, not by the data plane. Pointing it at the Portal inside `portal-ns` fails silently because the Deny-All Baseline there blocks istiod, and every request then returns 401 with no useful log line. The demo therefore embeds the public JWK directly in the `RequestAuthentication` (`jwks:` field), generated by `scripts/gen-keys.sh`.

## Consequences

Key rotation requires re-applying the `RequestAuthentication` with the new key added (dual-key window) and later removed. The README documents three production alternatives (Portal-served JWKS with an istiod allow rule; a JWKS host outside deny-all; an external IdP) and how rotation works under each. This is a demo-scoped deviation, not a production recommendation.
